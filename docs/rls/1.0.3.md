# Release 1.0.3 – Changelog Summary

This release introduces a formal plugin registration API, completes the move from legacy `font/icons/` paths to the flat `icons/` distribution, clarifies the two supported UI variants, and enforces 100% source coverage for statements, branches, functions, and lines.

* **Public Plugin Registration API**
  New `summernote.registerPlugin()`, `summernote.getPluginMeta()`, and `summernote.listPlugins()` methods provide a stable registration and discovery contract.
  Plugin metadata can declare buttons, scripts, stylesheets, and a version. Registered buttons are merged into editor options while explicitly configured buttons retain precedence.

* **Plugin Stylesheet Loading**
  New `summernote.loadPluginStylesheet()` and `summernote.loadPluginStylesheets()` helpers load plugin stylesheets on demand.
  Duplicate URLs are ignored, failed loads can be retried, and generated link elements are marked for reliable discovery.

* **Flat Icon Distribution**
  SVG assets now live in `src/icons/` and `dist/icons/`; the remaining legacy `src/font/` and `dist/font/` icon paths were removed.
  The generated `src/js/icons.js` manifest and `scripts/build-icons.js` keep source, runtime, and distributable icon lists aligned.
  Automatic icon URL detection now resolves the sibling `icons/` directory for both UI bundles.

* **Product & UI Positioning**
  Summernote Next is documented as one Vanilla JS editor core with two UI variants: `summernote-next` integrates with Bootstrap 5, while `summernote-next-classic` provides a standalone, UI toolkit-independent Classic UI.
  README, package metadata, Composer metadata, maintenance guidance, release documentation, and example copy now use this distinction instead of presenting the complete product as a BS5 editor.
  Generated Classic example titles were normalized to consistently include a space before their page-specific suffix.
  The Composer package suggests Bootstrap for the Bootstrap 5 integration instead of requiring it for Classic UI users.

* **Reproducible Browser Testing**
  The Docker image now installs the Playwright 1.61.0 Chromium binary, Cypress 15.17.0, and the required browser runtime libraries for the `application` user.
  Cypress and Playwright checks verify neutral product naming and confirm that the Classic UI does not load Bootstrap assets; Playwright captures screenshots for every tested Classic theme preset.

**Compatibility**: Existing editor initialization and public APIs remain compatible. Deployments that hard-code the legacy `font/icons/` asset path must move those SVG assets to `icons/`; code that treated the exported `ICONS` value as a mutable SVG cache should use `getIconSvg()`, `loadIcon()`, or `loadAllIcons()` instead. Composer users of the Bootstrap 5 integration must now require `twbs/bootstrap` directly because it is suggested rather than installed for every UI variant.
